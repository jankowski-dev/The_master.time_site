# Architecture

## Overview

The Master Time is a static Astro 5 site with a thin server layer for lead
delivery. Content is typed and validated at build time; the browser runs only
small, vanilla-TypeScript interactivity (calculator, lead form, price filter,
menu, analytics).

## Rendering strategy

- `astro.config.mjs` sets `output: 'static'` with the Node adapter in
  `standalone` mode. Every content page is prerendered to static HTML.
- API routes and the 404 page set `export const prerender = false` so they are
  served by the Node process (the 404 must return a real 404 status).
- The sitemap is generated by `@astrojs/sitemap` with a filter that excludes
  `/spasibo/`, `/zayavka/`, `/politika-konfidencialnosti/`.
- `security.checkOrigin` is enabled with `allowedDomains` derived from
  `SITE_URL` so the CSRF origin guard stays on without false positives on
  `localhost:4321`.

## Data flow

1. **Content** lives in `src/data/*.ts`, is parsed by Zod
   (`src/lib/content/schemas.ts`) and cross-checked by
   `src/lib/content/index.ts` (`loadContent()`).
2. **Pages** read the validated `content` singleton and render components. The
   calculator page also serializes a JSON payload (`#calculator-data`) that the
   client reads to run the estimate without a server round-trip.
3. **Leads** flow through the browser form → `POST /api/lead` →
   `handleLead()` → validation + rate limiting → `notifyLead()` fans out to the
   configured notifiers (email and/or Viber). Delivery succeeds if at least one
   channel succeeds.

## Environment & configuration

`src/lib/env.ts` reads `process.env` into a `LeadConfig` at request time. Each
channel is `null` unless every required value is present, so a missing
configuration never throws — the channel is simply skipped (or delivery fails
cleanly with a 502 in JSON mode).

## Security

- Server-side validation of every lead field (`src/lib/leads/validate.ts`):
  phone normalization, length caps, source enum, consent required, honeypot
  (`website`), and a minimum form-fill age (`startedAt`).
- Per-IP in-memory rate limiting (`src/lib/leads/rate-limit.ts`).
- Viber webhook requests are HMAC-SHA256 signature-verified.
- HTML email bodies escape all user-provided text (`formatLeadHtml`).
- Analytics only load after explicit consent; `track()` never sends PII.

## Seams for future work

- `LeadNotifier` (`src/lib/leads/types.ts`) is an interface — adding a CRM
  notifier means implementing `send(lead)` and registering it in
  `createNotifiers()`.
- `CRM_WEBHOOK_URL` is reserved but unwired; see `docs/ai-roadmap.md`.
